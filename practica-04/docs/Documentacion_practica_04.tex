\Needspace{6\baselineskip}
\subsection{Pruebas Unitarias}
\label{sec:org2cc13dd}

Una \textbf{Prueba Unitaria} verifica un comportamiento pequeño del sistema: una función, un método o una regla concreta. Para el desarrollo de las mismas se recomienda seguir el siguiente flujo:


\begin{figure}[H]

\centering

{\large
\textbf{Problema}
\,$\longrightarrow$\,
\textbf{Modelo}
\,$\longrightarrow$\,
\textbf{Casos}
\,$\longrightarrow$\,
\textbf{Pruebas}
\,$\longleftrightarrow$\,
\textbf{Implementación}
}

\caption{Flujo general del diseño de pruebas.}

\end{figure}

\textbf{Nota:} El resultado esperado se decide antes de ejecutar el código. No se copia lo que devuelve la implementación.

Los casos de prueba definidos se clasifican como:

\begin{itemize}
\item \textbf{Normal:} Un valor dentro de la regla.
\item \textbf{Frontera:} Justo antes, en y después de un límite.
\item \textbf{Inválido:} Un valor que el sistema debe rechazar.
\item \textbf{Excepción:} Un error esperado.
\item \textbf{Cruce de reglas:} Cuando dos condiciones se cumplen al mismo tiempo.
\end{itemize}

\textbf{Ejemplo:}

Si hasta 15 minutos es gratis, y desde 16 se cobra, probar 14, 15, 16 y 17.


\Needspace{6\baselineskip}
\subsection{Estructura de una prueba Arrange - Act - Assert}
\label{sec:org706b3ca}

\begin{itemize}
\item \textbf{Arrange:} Preparación de los datos, objetos, o estado inicial.
\item \textbf{Act}: Ejecución de la función o método que se desea probar.
\item \textbf{Assert:} Comprobación de que lo obtenido sea lo esperado.
\end{itemize}

\textbf{Ejemplo:}


\begin{lstlisting}[style=practica]
# Arrange
minutos = 16

# Act
resultado = sistema.calcular_total(minutos, "normal", False)

# Assert
assert resultado == 20.0
\end{lstlisting}

\textbf{Nota:} Una buena prueba responde tres preguntas: \textbf{¿qué regla comprueba?, ¿qué entrada utiliza? y ¿qué resultado debería producir?}


\Needspace{7\baselineskip}
\section{Objetivo}
\label{sec:org5849288}

El alumno diseñará un conjunto de pruebas unitarias para verificar el comportamiento de un sistema a partir de su especificación, no únicamente a partir de lo que hace el código.

Al finalizar la práctica, el alumno deberá ser capaz de:

\begin{itemize}
\item identificar casos normales;
\item identificar casos frontera;
\item detectar entradas inválidas;
\item verificar errores y excepciones;
\item escribir pruebas usando el patrón Arrange–Act–Assert;
\item justificar de qué regla del modelo proviene cada caso de prueba;
\item ejecutar una suite de pruebas y analizar sus resultados;
\item diferenciar entre “la prueba pasó” y “el programa es correcto”.
\end{itemize}

\subsection{Durante la práctica}
\label{sec:org6cbfe18}

\begin{enumerate}
\item Lea primero el modelo.
\item Diseñe los casos sin ejecutar todavía el sistema.
\item Escriba el resultado esperado de cada caso.
\item Implemente las pruebas.
\item Ejecute la suite.
\item Si alguna prueba falla, no cambie inmediatamente la prueba.
\item Compare:
\end{enumerate}

\begin{center}


\textbf{modelo esperado} vs. \textbf{resultado obtenido}
\end{center}

\begin{enumerate}
\item Determine si el problema está en:
\begin{enumerate}
\item la implementación;
\item la prueba;
\item la interpretación del modelo.
\end{enumerate}
\end{enumerate}

\subsection{Planteamiento del Problema}
\label{sec:org3e43e41}

Probar el Sistema de Ticket de Estacionamiento.

El sistema recibe:

\begin{itemize}
\item minutos de permanencia;
\item tipo de cliente;
\item si perdió el boleto.
\end{itemize}


\Needspace{6\baselineskip}
\subsubsection{Modelo del Sistema: Ticket de Estacionamiento}
\label{sec:org63efa77}

Comportamiento esperado:

\textbf{R1.} Los minutos deben ser un número entero mayor o igual que 0.

\textbf{R2.} Los tipos de clientes válidos son:

\begin{itemize}
\item \textbf{"normal"}
\item \textbf{"frecuente"}
\end{itemize}

\textbf{R3.} Si el boleto está perdido, el costo final es de \$300.00, sin importar los minutos ni el tipo de cliente.

\textbf{R4.} Si los minutos son 0, el costo es \$0.00

\textbf{R5.} De 1 a 15 minutos, el costo es \$0.00

\textbf{R6.} De 16 a 60 minutos, el costo es de \$20.00

\textbf{R7.} Después de 60 minutos se cobran \$20.00 por la primera hora y \$15.00 por cada hora adicional \textbf{iniciada}.

\textbf{R8.} Un cliente \textbf{"frecuente"} recibe un 10\% de descuento sobre el costo calculado, excepto cuando perdió el boleto.

\textbf{R9.} El costo nunca puede ser negativo.

\textbf{R10.} Si los minutos son negativos, el sistema debe lanzar un error.

\textbf{R11.} Si el tipo de cliente no es válido, el sistema debe lanzar un error.
